## 3. The 4 Signature Editorial Content Formats

Every piece of content must follow one of these 4 standardized formats:

### Format A: "Website Teardown" (Autopsy Format)
- **Target URL**: Anonymized or public e-commerce, SaaS, or agency site.
- **Structure**:
  1. *The Symptom*: Failed metric (e.g. 5.2s mobile LCP).
  2. *The Forensic Scan*: DevTools waterfall and VitalsSniper DOM inspector screenshot.
  3. *The Underlying Cause*: Exact script, uncompressed hero background, or 32 levels of DIV wrappers.
  4. *The Remediation*: Code before vs after.
  5. *The Result*: Verified metric delta.

### Format B: "We Measured It" (Empirical Head-to-Head Benchmark)
- **Setup**: Controlled testing environment (e.g., identical 2GB Hetzner or DigitalOcean droplet).
- **Structure**:
  1. *The Thesis*: Testing a widespread industry belief (e.g., "Does Elementor really slow down WordPress?").
  2. *Testing Parameters*: Server config, simulated network speed (4G throttle), DOM node counts.
  3. *The Raw Data*: Comparative table with TTFB, DOM count, Transfer Size, and LCP.
  4. *The Engineering Analysis*: Why the winner won.
  5. *Actionable Advice*: What developers should do on existing client sites.

### Format C: "Definitive Diagnostic Guide" (Search-Focused Evergreen)
- **Setup**: Targeting high-volume, high-intent technical search queries.
- **Structure**:
  1. *Quick Answer Box*: 40-word direct summary optimized for Featured Snippets and AI summaries.
  2. *Evidence Box*: What we tested across our research cohorts.
  3. *Step-by-Step Diagnostic Protocol*: How to find the issue in 2 minutes.
  4. *Native Tool Callout*: Try our free calculator or VitalsSniper inspector.
  5. *Code Solutions*: Copy-paste solutions (CSS, Apache/Nginx rules, WP filters).

### Format D: "Data-Driven Software Review & Comparison"
- **Setup**: Commercial review with FTC disclosure and sponsored links.
- **Structure**:
  1. *Testing Parameters Box*: Duration tested, test environment, sites deployed.
  2. *The Verdict*: 1-sentence verdict on who should buy and who should skip.
  3. *Empirical Performance Benchmarks*: K6 load testing charts or server TTFB measurements.
  4. *What We Liked vs What We Disliked*: Honest pros and cons.
  5. *Alternative Options*: Who does it better for different budgets.

## 5. Standard Operating Procedure (SOP) for Every Article

To maintain quality and strict compliance with our platform invariants, every published article must pass this 7-step checklist:

### Step 1: Mandatory Evidence Box Data
Every article must include a structured evidence component in its TypeScript data entry:
```typescript
evidence: {
  whatWeTested: "Detailed description of hardware, CMS, plugin version, and network profile",
  observedResult: "Concrete numerical outcome with units (ms, %, bytes, nodes)",
  source: "Web Audits Lab Benchmark / Audit Log ID"
}
```

### Step 2: Zero Punctuation Violations
- **Zero Em-Dashes**: Never use the unicode u2014 character.
- **Zero En-Dashes**: Never use the unicode u2013 character.
- **Allowed Punctuation**: Colons (`:`), commas (`,`), parentheses (`()`), and standard hyphens (`-`).
- **Validation**: Run the automated AST scan before staging:
  `node tests/verify_no_dashes.mjs`

### Step 3: FTC & Affiliate Compliance
- All commercial, affiliate, and external partner links must strictly include:
  `rel="nofollow sponsored noopener"` and `target="_blank"`.
- A prominent, human-readable affiliate disclosure banner must appear above the first outbound link.

### Step 4: Native Tool & Product Bridges
Each article must include at least two product touchpoints:
1. **Free Tool Widget Callout**: Inline card linking to `/tools/website-speed-test`, `/tools/lcp-checker`, or `/free-audit-report`.
2. **VitalsSniper PRO Contextual Mention**: 1-sentence explanation of how our browser extension automates the specific check in the user's active browser tab.

### Step 5: Responsive Layout & Zero Overflow (0 CLS)
- Max reading container width: `680px - 780px`.
- Overall layout container: `1160px - 1240px`.
- Tables and wide code blocks must use `overflow-x-auto` within a rounded container to prevent horizontal page scrolling on mobile (390px).

### Step 6: Structured Data Validation
- Ensure JSON-LD `TechArticle` or `Review` schema is populated with author entity references (`Devin Vance`, `Marcus Reed`, or `Elena Rostova`).

### Step 7: Automated SRE Verification
- Run `npm run build` to verify 0 type errors.
- Run `node tests/run_editorial_e2e.mjs` to ensure 200 OK and 0 layout overflow across all viewports.
